# Native AI configuration panels and usage reports

The existing admin-menu flag now selects native SQL for the restaurant AI panel, global superadmin AI panel and per-client superadmin AI panel. Shared usage/unbilled helpers also select native aggregation. The verified actor UID is passed explicitly; current local profile role/tenant, reset and disabled controls are rechecked through the same small guard used by chat administration. Global superadmin operations need no fabricated tenant. All operations reuse admin pool2/deadlines.

Key input/masking behavior is extracted into a pure module and re-exported at the original path. Omitted or displayed masked keys preserve the existing ciphertext, empty/null removes it, and new keys use the existing server AES-GCM helper. Owner key changes select own-key mode or clear back to the default, retain the administrative margin and clear prior key warnings. Superadmin mode/margin overrides keep their existing validation/null semantics. Key columns never enter the global tenant overview; it reads only key presence. Public responses retain masked keys and existing fields, and billing availability reads only a boolean. Native failures never select Source writes/reads.

Usage sums are computed with PostgreSQL NUMERIC before conversion to the existing number DTO. Date, tenant/null-platform, key-source, billable and invoice filters are preserved. Aggregation covers the actual matching events rather than silently truncating at the old Source 100,000-row request limit. Group/tenant results are bounded at 10,000 and invalid/nonfinite totals fail explicitly. No provider request, invoice creation, billing retry, key rotation, DDL, production data or flag change is performed by this work.

Eleven offline cases and seven disposable PostgreSQL cases cover key encryption/preservation/removal, owner and superadmin separation, current roles/controls, scope, decimal summaries, overview redaction, native Source-free selection and rollback. Chat guard regressions remain in CI. Fixture cleanup leaves the schema pristine for the independent identity migrations. Provider key-test actions retain the existing verified server path; no real test is invoked. AI invoice settlement, addon checkout/cancellation/webhook metadata and other Source consumers remain explicit follow-up work before native rollout.
