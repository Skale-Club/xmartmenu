# Native staff handling for waiter calls

`OWNED_ADMIN_WAITER_CALLS_ENABLED=true` selects native staff GET/PATCH routes. It is false by default; this PR changes no flag, production data or schema. Both routes reuse getEffectiveTenant and the existing shared admin PostgreSQL pool (max2). Native Auth takes the actor UUID from getOwnedPrincipal; an absent/revoked/disabled/recovery principal denies access without Source fallback. Explicit legacy Auth selection uses the actor recorded by the existing guard inside withApi. No client-supplied actor, tenant or role is accepted.

The SQL transaction rechecks the actual account/profile and tenant membership. Superadmin preview remains permitted; ordinary staff and owners can access only their current tenant. Subscription/plan and settings use the same capability resolver as the old routes. An Orders/Payments plan can still handle calls after ordering switches are off (the existing kds gate). Mutations hold share locks over actor and plan state through commit.

GET preserves {calls}, oldest first, max100 and the exact two-hour activeCalls filter. PostgreSQL timestamps are explicitly converted to ISO strings before activeCalls sorts them. PATCH preserves {call}, accepts acknowledged/done from any current status (including done->acknowledged), retains other timestamps exactly as before, and records the server actor only for acknowledgment. Invalid bodies and cross-origin mutations are rejected; JSON is bounded to2048bytes and5seconds. No staff SSE route exists: WaiterCallsPanel already uses authenticated visible polling and is unchanged.

Actual candidate metadata was confirmed read-only: waiter_calls_acknowledged_by_fkey is validated, single-column acknowledged_by -> auth.users(id), delete SET NULL, update NO ACTION. docs/proposals/native-waiter-actor-owned-only.sql proposes retargeting only that FK to public.app_accounts(id). It locks affected tables, refuses unreconciled actor UUIDs, validates the new FK and compares full-row hashes of calls/accounts/profiles/Auth stubs. It does not create Auth stubs or change existing UUIDs/roles/memberships. The other Auth FKs and automatic migration paths are untouched. This proposal HAS NOT BEEN APPLIED. Keep the staff flag disabled until this exact candidate DDL is reviewed/applied; fresh native actor acknowledgments otherwise fail the legacy FK.

Unit and disposable PostgreSQL tests cover tenant/role/actor injection, disabled/recovery access, recent/stale/done list boundaries and100-row ordering, current plan revocation, state transitions, native UUID FK blocker, orphan refusal, preservation during DDL, rollback and SET NULL deletion semantics. No .env or live database is used. No new external paid service or billing path is introduced.
