# Native public chat messages and audio

The existing admin-menu owned flag selects native message/audio handlers before a Source client is constructed. All metadata, conversation history, addon/plan/blocklist/quota gates and public catalog reads run in a bounded read-only repeatable-read transaction on the existing admin pool2. That transaction ends before AI work begins. AI configuration, rejected-key warnings and usage accounting use the native access slice; no new provider model, credential, retry or cost rule is introduced.

Catalog selection keeps the existing requested-public-menu/default/first-active fallback. Private menus are never anonymous chat catalogs. Category/product/group/option/ingredient joins bind tenant and menu; unavailable options/ingredients are omitted. Price multiplier, base/option prices, groups, history ordering and shared cart validation remain authoritative on the server. Source/native paths share the extracted pure prompt assembly, including location profile/hours, delivery context and language. No client-supplied history becomes trusted history.

Native message ingress retains both IP rate limits, message-size checks, channel selection and conversation-bound voice signature. After provider completion, a new transaction rechecks tenant/addon/conversation/blocklist/channel/quota controls and inserts user plus assistant turns atomically. Conversation locking prevents aggregate lost updates; a tenant/hash advisory lock serializes the final per-phone daily cap across conversations. No SQL transaction spans provider work, and no mutation retries or Source fallback occur. A failed final write returns an error rather than acknowledging unrecorded turns. Concurrent in-flight provider calls can still consume credits before the final quota recheck; this slice does not introduce a provider reservation or claim exactly-once billing.

Audio retains the multipart size check, transcription model, trimming and signed transcript response. Native admission also checks the current tenant phone blocklist before spending provider credits. Audio is never persisted. Native JSON message ingress reuses the bounded 64-KiB/five-second body reader; multipart parsing retains the existing app-level behavior and five-MiB audio check.

Nine offline handler/route cases and eight disposable PostgreSQL cases cover native selection/denial, voice binding, provider/persistence failures, exact catalog prices and tenant/private boundaries, daily counts, concurrent pair persistence and final quota, late control changes, rollback and audio admission. No real provider, Stripe, Source/Auth request, DDL, production write or flag change is performed. Fixtures prove query behavior, not live grants/provider acceptance. Staff chat moderation/settings, invoice settlement, remaining source consumers and final source write barrier/reconciliation remain required migration work.
