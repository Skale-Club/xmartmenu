# Native shared tenant plan and capabilities

The existing admin-menu flag selects native SQL before the shared tenant-plan helpers construct a Source client, including when an old caller supplies an explicit legacy client. The same admin pool2/deadlines are reused. A pure override/live-feature model is shared by both branches, preserving zero overrides, null defaults, prices/fees, live versus revoked status, billing cycle and grandfathering. Native SQL numerics become finite number DTOs; missing subscriptions/plans remain null and ambiguous/corrupt facts fail explicitly.

Capabilities resolve from the same pure service-mode functions and current native settings in one read-only snapshot. Explicit supplied settings, including null, retain their existing meaning. Native failures never fall back to Source. Existing helpers that intentionally catch plan failure continue to deny paid capabilities.

Reconciliation computes the canonical downgrade patch and writes only those boolean switches. Fees/ETAs, dine-in/pickup and unrelated tenant values remain intact; no subscription/settings row is created. Current-plan reconciliation locks the tenant before plan/subscription rows and settings update. Query-based exports permit a future lifecycle webhook to compose its work atomically; that writer must acquire the tenant lock before changing its subscription rows. Native mutation failures report the existing ok=false shape rather than using Source writes or retrying SQL.

Seven offline cases and five disposable PostgreSQL cases cover zeros/nulls/status/grandfathering, shared legacy model compatibility, Source-free selection, capabilities, current/explicit ceiling reconciliation, tenant isolation and rollback. No provider/Stripe request, subscription charge change, role/DDL, production write or live flag change occurs. This removes helper dependencies, not the remaining SaaS webhook/invoice-settlement or unmigrated caller surfaces. Final Source fence/reconciliation and reviewed rollout remain required.
