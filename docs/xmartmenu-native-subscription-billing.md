# Native subscription surfaces (prepared, rollout disabled)

This slice owns settings/subscription SSR, tenant subscription GET/PATCH/checkout/portal and superadmin tenant subscription GET/PUT, plus the shared plan-change decision. The existing admin-menu flag selects SQL before Source factories. It preserves the explicit Source path when false, without a fake SDK or fallback after native refusal. Tenant/staff reads and owner/superadmin writes use verified app UUIDs with current local profile/disabled/reset/role controls. All readers/writers share the existing admin pool2; network never holds a transaction.

The shared pure price decision retains dunning-before-no-op, first plan item, create_prorations/error_if_incomplete and metadata contracts. Native financial requests additionally freeze proration time and checkout expiry so retries cannot silently change those defaults. Existing no-Stripe preferences and admin overrides remain local without requiring Stripe credentials. Read DTOs retain active-plan sorting, numeric zero/null overrides, missing-subscription responses, provider status warnings and tenant limits. The SSR client accepts only the five subscription fields it renders.

The separate [OWNED-only SQL proposal](proposals/native-subscription-billing-owned-only.sql) stores exact request bodies, local/source snapshots, provider account/mode/version and hash, with CAS token/30-second lease and at most one pending request/open checkout per tenant. Runtime can advance state but cannot replace facts. No raw provider URL, credential or payment detail is retained; session/subscription IDs come only from actual provider responses. Nullable current actor/tenant FKs preserve deletion while immutable origin UUIDs retain the operation proof. Candidate apply is separate and must preserve all47 business tables,95 Source migration records/roles and existing backup/restore policies.

Stripe calls are6 seconds, no SDK retries, version pinned. Requests commit before the call; completion/optional superadmin local patch/reconciliation commit atomically. A crashed durable attempt can replay only the identical saved parameters/key in the same provider context within20 hours. A current SDK exception or returned-fact/local mark mismatch records reconciliation_required without false success or blind retry. A confirmed card rejection under error_if_incomplete records rejection without applying a plan. Profile revocation and stale local/price facts deny before a new effect.

Checkout lifecycle preserves actual sessions: an open same-plan session returns its real URL; a different target first expires the old session and confirms closed status. A payment racing expiration is recognized with a bounded exact-session read and cannot open a parallel checkout. Completed session/subscription references remain known even before webhook delivery, so refreshing cannot create a second subscription. These are specific closed-state proofs, not general automatic financial reconciliation. Missing local subscription rows get a cancelled, non-entitled target before checkout so the existing lifecycle webhook has a row to activate. Paid entitlements still follow the provider webhook.

Portal creation preserves the actual customer/URL and rechecks current authority before returning it. Every native phase revalidates the server-derived session hash against current app_sessions, account session_version/expiry and the exact enabled project/subject binding, alongside the current local role/profile. Native billing requires native Auth; no Source authority fallback is used. No session token/hash is stored in billing facts or provider requests.

Superadmin writes record the native CRM intention in the same SQL transaction as the subscription change and financial receipt, using the actual durable request ID as event key when present. This reuses the transactional tenant-effects seam from PR64; its proposal extending effect kinds/event_id/tags and native dispatcher must be reviewed/applied before enabling this path. The legacy QStash/Source-reading worker is never called by this native HTTP slice. Cache invalidation after commit cannot turn an already committed billing action into a false 503. This does not own plans CRUD, directory/staff panels, registration, production infrastructure or flags.

Fourteen new offline cases prove provider facts/budgets, source-free routing, staff restrictions, forged ID rejection, session hash derivation and shared decision fidelity. Twenty-seven disposable PG cases cover native views/local paths, concurrent checkout reuse, confirmed replacement, completion/retirement races, webhook lag, live plan changes/dunning, uncertain outcomes, local rollback/current authority, deleted/expired/version-revoked/disabled-binding sessions between prepare and claim and during provider effects, and atomic native CRM intentions. Tests inject all provider calls; none bills Stripe. Full CI must also run the unchanged legacy plan-billing tests (the local shared dependency install lacks a Sentry transitive dependency).

Before rollout: apply/review the ledger with fresh restoration-proven backup; reconcile Source business data/fence; count unresolved legacy batches and duplicate provider associations; and explicitly enumerate/resolve pre-existing platform checkout sessions not represented in this ledger. Stopping the old app does not expire external Stripe links. Unknown live subscriptions/sessions, expired/uncertain effects, and operator changes need actual provider read evidence before another financial action. No production effect or schema apply was executed by this code publication.

Primary contracts: [subscription update/proration](https://docs.stripe.com/api/subscriptions/update), [confirmed checkout expiry](https://docs.stripe.com/api/checkout/sessions/expire), [bounded idempotency retention](https://docs.stripe.com/api/idempotent_requests).

Authority writes share the account-admin advisory, then actor SHARE, tenant NO KEY UPDATE, subscription/plan and settings locks. The small Connect integration uses the same order; no transaction holds a provider call.
