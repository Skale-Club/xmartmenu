# Native Stripe Connect slice (in preparation)

Remaining direct consumers in this bounded slice are `/api/stripe/connect/oauth`, `/callback`, `/disconnect` and the shared currency/connection/feature readers in `lib/stripe.ts`. These currently construct a Source SDK before owned authority/data can select its path. Subscription SSR/API/checkout/plan changes are separate consumers, not completion evidence for this slice.

The existing admin-menu flag and shared pool (max two) select native SQL. Owned mode never falls through to Source on failure. Every owner operation verifies the current local profile/app controls for a verified UID; role/tenant come from that profile, never email or caller metadata. Domain-separated HMAC state binds the same actor, tenant and random nonce with a15-minute TTL; callback rechecks current authority and plan before token exchange and before persisting the connection. Legacy flag-off routing/state behavior remains unchanged.

Token exchange/deauthorization use injected provider gateways with6-second timeouts and zero SDK retries, outside SQL transactions. Local disconnect commits before the existing best-effort provider revoke. Connection/account ambiguity refuses instead of selecting another tenant; no provider secrets or OAuth tokens are stored in the business table. No provider call is made by tests, and this preparation changes no real flags, credentials, data, role, DDL or Stripe configuration.

[Stripe's OAuth reference](https://docs.stripe.com/connect/oauth-reference) says consuming an authorization code more than once can revoke the connection. The separate [OWNED-only proposal](proposals/native-stripe-oauth-owned-only.sql) therefore records unique nonce/code SHA256 hashes before exchange. A committed claim permits exactly one call; concurrent, expired and uncertain deliveries never exchange again. Completion writes the connection and consumed receipt in the same transaction. A completed duplicate can only acknowledge the same current active account; it cannot reconnect after disconnect. Failure after exchange records reconciliation_required without automatic revoke/retry. No raw code, OAuth access token or refresh token is persisted. Missing schema/grants refuse; candidate DDL, backup/business/role preservation and actual provider acceptance remain rollout gates.

Metadata reads retain plan ceilings, active-connection predicates, currency default and exact tenant filtering. Tenant mutation serialization uses FOR NO KEY UPDATE, compatible with existing FK key-share inserts and conflicting with deletion. No broad SDK shim, extra pool or financial billing behavior is introduced.

Nineteen offline cases cover state separation/expiry, current principal binding, Source-free routing/metadata, request budgets, duplicate/uncertain callback handling and post-commit revoke/CRM behavior. Nine disposable PG cases cover native metadata, actor/tenant controls, plan loss, lifecycle writes, account-association races, rollback and durable single-use completion. No test calls a provider. This slice does not complete the still-legacy subscription SSR/API/checkout/plan-change consumers.
