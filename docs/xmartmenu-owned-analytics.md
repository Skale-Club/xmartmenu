# Native Analytics dashboard reads

`OWNED_ADMIN_MENUS_ENABLED` selects the dashboard's native data branch. Its default and all live flags remain unchanged. The branch reuses the existing administrative pool (maximum two connections) and its eight-second transaction budget; it creates no pool, grant, function or schema object in production.

The six existing RPC selections cover five canonical functions: current and previous `get_menu_analytics_overview`, product analytics, upsell, order attribution and engagement. Their SELECT bodies are stored as static, schema-qualified SQL with bound typed parameters. Canonical source-body hashes are recorded beside them and verified offline. Runtime never executes a source RPC, reads a migration file or creates a compatibility SDK.

An authorized tenant-member/superadmin context is required before any query. All metadata and aggregates use that tenant UUID. Menu/location filters remain parameters; order attribution intentionally has no menu filter, matching its original function. Current/previous periods, event versus order revenue, cancellation exclusions, test-session exclusion, duration clamping, timezone buckets and product ordering retain the source SQL semantics. Numeric JSON projections preserve the existing dashboard normalizers.

Metadata, active/trial plan features, service switches, current/previous values and every aggregate are read in one read-only repeatable-read snapshot. The same plan/capability and experience-setting gates drive the existing UI. Missing subscriptions keep the existing default ceiling; ambiguous or malformed native metadata/query failures fail closed without switching to source data or reporting empty success. The flag-off path retains all six original RPC calls and its existing unavailable-state behavior. Analytics display/settings writes already use the administrative settings adapter from PR34.

The disposable PostgreSQL cases compare all five native aggregates with unmodified source RPC definitions across all/menu/location/foreign-menu/empty filters. They also cover current versus previous windows, cancelled-plan gates, concurrent event insertion under a stable snapshot and native reads with table SELECT privileges while RPC EXECUTE is denied. These projection fixtures do not claim full production DDL/RLS or traffic acceptance.

This slice completes dashboard reads only. Public analytics ingestion still writes through the legacy service and requires a separate native writer preserving session identity, event validation, idempotency and monotonic updates before the source write barrier/cutover. Trusted order/payment event writers already have their own selected adapters. No application data, credentials, roles, production flags, provider services or deployment is changed by this PR.
