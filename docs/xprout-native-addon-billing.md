# Native chat-addon subscription metadata and controls

The existing admin-menu flag selects native metadata before Source construction for chat-addon checkout/cancellation and the superadmin tri-state override. Verified actor UID/current local role/tenant/reset/disabled controls use the same shared guard as chat/AI administration. Read-only admission uses the existing pool2 and ends before Stripe calls. No DDL, new pool, real provider request, charge, production data or flag change is performed.

Checkout retains plan/override availability, configured price, already-active 409 guard, stored customer, quantity, subscription/session metadata and success/cancel URLs. Cancellation remains available even after plan/addon access is revoked and requests end-of-period cancellation for every active customer subscription marked addon=chat, preserving historical duplicate handling. Neither route changes paid-active state directly; the lifecycle webhook remains responsible. SDK call/request/idempotency behavior is preserved, with no added SQL/provider retry. Existing checkout concurrency/pagination/provider ambiguity behavior is not redesigned in this metadata migration. The GET checkout helper reads a response clone, so an error body remains usable when no redirect occurs.

Superadmin override accepts true/false/null and updates only chat_addon_override on the supplied tenant subscription. Existing update-only/no-row success is retained; it does not create subscriptions or alter plan/customer/paid-active/period fields. Native errors never switch to Source.

Eight offline cases and five disposable PostgreSQL cases cover exact Stripe request facts with mocked gateways, availability/active/customer gates, duplicate end-of-period cancellation, verified attribution, readable GET errors, Source-free selection, local controls, tri-state scope and rollback. Fixtures clean up before independent identity migrations.

SaaS/Connect webhook metadata and AI invoice settlement remain required before rollout. In particular, the historical billAiUsage function retains a UUID batch but recomputes FX, invoice/customer/currency/description facts on retry; native migration needs an explicit review of persistent request facts and provider reconciliation. This slice leaves that function and invoice/charge behavior untouched. Final Source fence/reconciliation and real provider acceptance remain separate gates.
