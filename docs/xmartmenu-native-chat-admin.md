# Native chat settings, inbox and moderation

The existing admin-menu flag selects native chat configuration/status, inbox lists/threads/CSV, notes and phone block/unblock before Source data clients. The unchanged browser screens already use these HTTP APIs. Shared addon status also selects native SQL, so the inbox SSR no longer requires Source metadata. The settings page uses the same guarded native projection. All operations share admin pool2/deadlines; no DDL, credential rotation, provider request, production data or flag changes occur.

The server obtains the actor from the currently selected authentication authority. Owned Auth requires the freshly verified owned principal and never falls back to Source after denial. SSR does not rely on API-only logging context. While legacy Auth is explicitly selected, existing verified legacy identity remains usable. Every native administrative operation independently checks the actor's immutable profile UID, current local role/tenant, reset requirement and app-account disabled status. Mutations hold those rows while executing. Only store administrators and verified superadmin previews pass; no email match or role promotion exists.

SQL projects fixed non-secret settings fields, ignoring both legacy key columns and any supplied tenant/credential fields on writes. Existing switches/model/provider/rate-clamp behavior is preserved. Inbox reads filter tenant on conversations and message joins, retain pagination/order, and bound whole threads/blocklists at 10,000 rows with an explicit unavailable response on overflow. Notes return not-found for foreign/missing rows. Existing CSV formatting is shared by both branches.

Block attribution uses the verified existing profile UID (`blocked_by -> profiles`), with no legacy `auth.users` insertion. Blocklist upsert and all matching tenant/hash conversation status updates commit together; unblock/delete and reactivation also commit together. The existing block timestamp survives repeated moderation. Session creation, final public message persistence and moderation now all acquire the fixed tenant/hash advisory lock before conversation row locks. Public save re-reads the immutable tuple after locking and refuses a changed hash; this ordering prevents a moderation/save deadlock across different same-phone conversations.

Eleven offline cases cover native principal selection/terminal denial, current local controls, non-secret projections, whitelist writes, scope and Source-free routing. Six disposable PostgreSQL cases cover settings preservation/clamping, list/thread/note isolation, live roles/controls, attribution/block/unblock behavior, atomic rollback and concurrent moderation/public persistence. Existing public chat PostgreSQL cases remain in CI to exercise the adjusted lock order. Fixtures do not prove live grants or provider acceptance. Addon checkout/cancellation, superadmin override, AI panel settings/invoice settlement and staff waiter acknowledgment remain separate migration work; final Source fence/reconciliation and reviewed rollout are still required.
